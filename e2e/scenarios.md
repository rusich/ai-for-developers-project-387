# Пользовательские сценарии (интеграционные, Playwright)

Приложение проверяется в реальном браузере (Chromium) против живых
Rust-бэкенда (порт 3000) и статики фронтенда (порт 8080). Серверы поднимает
Playwright через `webServer`, состояние бэкенда переживает шаги одного прогона
(in-memory хранилище). Тесты идут последовательно (`serial`).

## Основной сценарий бронирования (обязательный, `booking-flow.spec.ts`)

1. **Вход владельца и создание типа события** (`admin.html`)
   - неверный токен → ошибка «Неверный токен владельца», вход отклонён;
   - верный токен (`dev-token`) → открывается кабинет;
   - создание типа события «Консультация …» → тип появляется в списке.

2. **Гость записывается** (`index.html`)
   - видит созданный тип события → выбирает его;
   - выбирает первый свободный слот (30-минутная сетка, окно 09:00–18:00 UTC, 14 дней);
   - заполняет имя и email → «Забронировать»;
   - видит экран «Готово!» с подтверждением.

3. **Конфликт занятого времени (409 в UI)**
   - «другой гость» занимает первый свободный слот через API напрямую,
     пока текущий гость уже видит его доступным на экране;
   - текущий гость подтверждает бронь → приложение показывает
     «Это время уже заняли» и возвращает к выбору слота.

4. **Владелец видит встречу** (`admin.html`)
   - в таблице «Предстоящие встречи» появляется строка с данными гостя
     (имя, email, тип события).

## Тёмная тема (`theme.spec.ts`, независимо от бэкенда)

1. **Гость, системная тёмная тема** (`index.html`)
   - при `prefers-color-scheme: dark` по умолчанию работает тёмная тема
     (режим «Тема: авто», кнопка в состоянии `aria-pressed="true"`);
   - клик по переключателю циклит режимы: авто → светлая → тёмная → авто;
   - выбор сохраняется между перезагрузками страницы (localStorage);
   - в режиме «авто» смена системной настройки меняет тему без клика.

2. **Владелец, переключатель на админке** (`admin.html`)
   - кнопка переключения темы работает и на странице владельца.

## Что дополнительно проверяется по пути

- **CORS**: фронт на 8080 и API на 3000 — разные origins; `localStorage.apiBase`
  задаётся как в dev-сценарии, все запросы идут через реальный браузер.
- **Локальное время**: браузер работает в UTC, UI форматирует слоты
  через `Intl.DateTimeFormat`.
- **Валидация форм**: HTML5 (`required`, `type=email`) через `reportValidity`.
