# Роадмап развития приложения

## Контекст

Приложение «Календарь звонков» функционально завершено. Этот этап проекта
посвящён командной работе с OpenCode на GitHub: каждая задача из роадмапа
оформляется как GitHub issue, реализуется агентом в PR, проходит ревью и
попадает в `main` через мёрдж. Продуктовый функционал **не расширяется** —
в работе только UI/UX.

## Ограничения

- **API-контракт не меняется** (`spec/main.tsp` → `openapi.yaml` — единый источник правды).
- Поведение эндпоинтов и бизнес-логика остаются прежними.
- Все тесты должны оставаться зелёными: `just test`, `just test-smoke`, `just e2e`.

## Задачи (каждая → GitHub issue → PR)

### 1. Дизайн-система: современный вид

Карточки, тени, скругления, отступы, типографика и цветовая палитра через
CSS-переменные. Единый стиль для гостевой страницы и админки.

### 2. Тёмная тема

Поддержка `prefers-color-scheme` + ручной переключатель (выбор сохраняется).

### 3. Выбор слота и дней

Календарная сетка, состояния выбранного/недоступного дня, подсветка «сегодня»,
понятная пустая сетка слотов.

### 4. Форма бронирования и экран подтверждения

Состояния загрузки, ошибки валидации у полей, аккуратный экран «Готово!».

### 5. Админка

Таблицы, формы, пустые состояния, явные кнопки действий для типов событий и встреч.

### 6. Мобильная адаптивность

Адаптивные сетки, тач-таргеты ≥ 44px, читаемые таблицы на малых экранах.

### 7. Доступность

Контраст, focus-состояния, aria-атрибуты, валидный HTML, семантические лейблы.

### 8. Микро-анимации и переходы

Плавные переходы между шагами бронирования, hover/focus-эффекты.

### 9. Мета-теги и favicon

Заголовки, описание, og-теги, favicon для обеих страниц.

## Как выполняется

1. Для каждой задачи создаётся GitHub issue с критериями приёмки.
2. Агент реализует задачу в PR (Conventional Commits).
3. Пользователь ревьюит; при замечаниях агент дорабатывает в том же PR.
4. Пользователь мёрджит PR; CI (тесты + e2e) должен быть зелёным.
5. После мёрджа — ручной деплой на Railway (`railway up`).

## Проверка результата

- `just test` — cargo test бэкенда.
- `just test-smoke` — smoke-тест API-клиента.
- `just e2e` — браузерные сценарии.
- Визуальный осмотр гостевой страницы и админки в dev-режиме (`just dev`).
